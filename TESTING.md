- Build wie im Deploy: `npm run build` (Vite, danach `scripts/static-routes.js`)

- Secret-Scan: `gitleaks git .`, vor jedem Commit per `pre-commit install`
- Audit: `npm audit --audit-level=critical`
- E2E und Aufzeichnungen: gibt es noch nicht. `npx playwright test` kommt mit Schicht 8, Aufzeichnungen mit Schicht 4a

## Gegen Produktion
- Heute läuft kein Test gegen Prod. Außer dem Deploy selbst berührt nur ein Schritt Fremdsysteme: jeder Deploy schickt die Stripe- und PayPal-Secrets per POST an die beiden Apps-Script-Backends (`action: setup`, `deploy.yml:125-155`); scheitert das, bleibt der Deploy grün.
- Beim Laden schreiben die öffentlichen Seiten in kein Fachsystem. Netzzugriffe beim Laden: `HEAD /favicon.svg` (`src/components/NetworkRecovery.tsx:31`), die lesende RPC `website_projektpositionen` auf Projekt- und Artikelseiten (`src/hooks/useProjectCosts.ts:9-25`), Google Fonts (`index.html:31-34`) und Google Analytics, das Seitenaufrufe meldet (`index.html:76`). Das PayPal-SDK lädt erst, wenn PayPal als Zahlungsart gewählt ist (`src/pages/Donation.tsx`, Zweig `paymentMethod === "paypal"`; voreingestellt ist SEPA über Stripe, `useState` von `paymentMethod`). Geschrieben wird erst nach einem Klick: Zahl-Buttons (`src/pages/Donation.tsx`: `StripeCheckoutButton`, `paypalService.createSubscriptionPlan`), Spende oder Überweisung registrieren (`createDonationIntent`), Newsletter (`subscribeToNewsletter`, `src/components/NewsletterForm.tsx:63`), Mitgliedsantrag (`src/pages/Membership.tsx:248`), Kontaktformular (`src/pages/Contact.tsx:68`), Anmeldung unter `/admin`.
- Geplant für die Schichten 7 und 8 (Freigabe offen): nur lesend, keiner dieser Klicks. Abgesichert durch einen Netz-Guard in Prod-Läufen: er bricht jede Anfrage außer GET und HEAD ab, und trifft eine davon einen der Schreibwege oben (`form-submit`, Apps Scripts, Edge Functions, EmailJS), wird der Test rot. Einzige Ausnahme ist die lesende RPC `website_projektpositionen`, weil supabase-js RPCs als POST schickt. Google Analytics wird gesperrt, damit stündliche Aufrufe die Statistik nicht verfälschen. Cookie-Einwilligung und Sprache setzt der Test im eigenen Browser-Speicher (`cookie_consent`, `alma-language`).
- Alarmweg: fehlgeschlagener Workflow → GitHub-Benachrichtigung. Telegram (@agent_runtime_bot) und das Erkennen eines ausgebliebenen Laufs: siehe Schicht 8 unten.
- Testdatensätze: keine nötig. Muss ein Test je schreiben, dann nur mit Freigabe, mit Präfix `TEST-` bzw. den Testadressen aus alma-data-platform (`live-test@almabridgeofhope.org`, `info+ci-<uuid>@almabridgeofhope.org`).
